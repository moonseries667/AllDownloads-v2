# AllDownloads 前端工作台

Issue [#3](https://github.com/moonseries667/AllDownloads-v2/issues/3) 的桌面工作台，八个业务路由统一调用 Java 公共 `/api/v1`。默认开发和发布构建均使用真实 HTTP 模式；演示必须显式选择。开发与隔离联调位于 Carbon，正式运行由协调者在 Y7000P 部署；本分支不访问真实平台账号或媒体。

## 真实 Java 模式与发布构建

在本工作树的 `frontend` 目录使用 Node.js 24：

```powershell
npm ci
npm test
npm run build
```

`dist` 为发布目录，浏览器通过相对 `/api/v1` 调用同机 Java。部署服务器需将 `/api` 交给 Java，其余业务路由回退到 `index.html`。不要向前端配置内部 runner token、账号 Cookie 或 Carbon 路径。生产构建不打包演示 transport 与种子数据；接口失败保留明确错误，不切换为演示或制造账号、任务和完成状态。普通 `build` 遇到 `VITE_API_MODE=demo` 会失败，防止误发演示产物。

构建会从实际生效配置生成 `dist/release-build.json`，记录 `apiMode` 与 `apiBase`。根集成打包可将整个 `dist` 作为 prebuilt 输入；正式包应为 `{"apiMode":"http","apiBase":"/api/v1"}`，不手工改写此文件冒充构建模式。

开发/临时预览可复制 `.env.example` 为不入库的 `.env.local`，启用 `DEV_JAVA_PROXY=http://127.0.0.1:8080`。Java 的 `alldownloads.allowed-origins` 需包含前端的准确 origin（开发默认 `http://127.0.0.1:5173`）；不使用通配符。执行 `npm run dev`；临时验证发布包可使用 `npm run preview`。Vite preview 用于验证构建，正式部署使用协调者确定的静态托管方式。

当前消费基线为 `9e8234c`，账号增量依据协调者冻结的 `contracts/ACCOUNTS.md`。Bilibili 只用 `bilibili-main`；Telegram、夸克、Drive 分别为 `telegram-main`、`quark-main`、`drive-main`。账号普通读取不主动检查平台，检查只发 `CHECK_ACCOUNT`。登录使用服务端 AuthSession：本地生成官方二维码、由用户打开官方授权页、明确显示 LOCAL_SETUP、有限读取/轮询、带 revision 取消。页面不接收密码、验证码、Cookie 或 OAuth code/token，不持久化授权 URL。

真实 Java 当前没有全局 `/search` 和移除来源接口，因此搜索框提供携带关键词进入平台筛选，移除来源明确禁用。旧版 Java 缺少 `/accounts` 时设置页显示接口缺失，不能显示假账号；账号功能需要包含冻结账号实现的新版 Java。总览只使用已提供的运行与 Bilibili 摘要，任务与问题由完整分页事实计算；任务空进度和持久问题的扁平结构已按实际响应处理。

## 隔离 Java 浏览器联调

先准备构建好的 Java jar 与 Java 21，在 `frontend` 目录设置实际绝对路径后执行：

```powershell
$env:ALLDOWNLOADS_TEST_JAVA='<Java21>/bin/java.exe'
$env:ALLDOWNLOADS_TEST_JAVA_JAR='<已构建后端>/target/alldownloads-backend-0.1.0-SNAPSHOT.jar'
npm run test:java
```

测试启动真实 Java、全新 SQLite 和真实模式发布包，浏览器入口为独立的 `127.0.0.1:5193`；进程结束后自动关闭。独立数据和 Java 日志保存在被忽略的 `node_modules/.cache/java-browser-*`，从不读取既有会话或内部 token。截图与响应附件保存在被忽略的 `test-results`。覆盖八个空库页面、来源逐条结果/别名/置顶持久化、空进度任务/取消、无目录时拒绝预览、原生选择不可用和真实 Java 停止后的错误展示。另有明确标为 `contract stub` 的登录组件用例验证本地二维码与取消请求，它不代表平台授权已成功。无 Go/真实账号时不能把这些验证当成媒体下载、云端归档或 Y7000P 验收。

包含账号增量的 Java jar 使用同样的环境变量执行 `npm run test:java:accounts`。该独立场景验证四个固定逻辑账号的真实响应、普通读取不排检查、主动检查返回持久 taskId，以及等待执行中的登录会话和带版本取消。旧 jar 的 404 会明确失败，不会用替身满足这项验收。

本轮 Carbon 验证：102 项单元/适配测试、类型检查、发布构建、仓库结构检查通过；35 项历史 demo 浏览器场景通过。真实 Java 基础场景 5 项通过，其中 4 项使用实际 Java HTTP/SQLite，1 项明确为登录组件契约替身。2026-10-17 复用含 Java 账号实现 `38b39cd` 的协调集成 jar，账号独立浏览器场景 1 项通过：四个固定账号、只读不排任务、主动检查、登录等待及带版本取消均使用实际 Java/SQLite。该场景不启动 Go，也不访问真实平台；成功媒体下载、设置保存、平台授权、Y7000P 和长期运行仍未据此宣称通过。

显式演示入口为 `npm run dev:demo`；`npm run build:demo` 仅生成演示验收包。`npm run test:e2e` 的历史工作台场景使用明确的 demo mode，与上述真实 Java 浏览器测试分别记录。

## 本机运行

需要 Node.js 24，npm 依赖由 package-lock.json 固定。在 frontend 目录运行：

```powershell
npm ci
npm run dev
```

打开 [本机工作台](http://127.0.0.1:5173/)。服务只监听 127.0.0.1，默认连接 Java；未配置代理或 Java 不可用时显示错误。显式 `npm run dev:demo` 才使用 localStorage 的 alldownloads.demo.feedback2.v3 演示键，保留模拟订单与验收场景；演示不会执行真实业务。

```powershell
npm test
npm run build
npm run test:e2e
```

- npm test：非 watch 的 Vitest 业务边界测试。
- npm run build：vue-tsc 类型检查及 Vite 生产构建；输出 dist。
- npm run test:e2e：Playwright 使用本机已安装的 Chrome，无需登录态。在专用 5184 端口在测试进程内启动本工作树的开发服务，拒绝复用其他工作树服务。服务随测试进程关闭。失败截图保存在被忽略的 test-results。
- TypeScript 固定为 5.9.3。实测当前 vue-tsc 3.3.13 无法读取 TypeScript 7 的 tsc 入口，因此没有采用不兼容组合。
- Element Plus 当前完整引入；构建有约 1 MB 未压缩公共块的体积提示。路由页面已分包，提示未被关闭。

## 异常场景验收

在“设置 → 前端验收场景”切换。切换前会确认重置本浏览器的演示记录；真实文件和账号不受影响。

| 场景           | 验证位置与结果                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 默认示例       | 未下载、部分完成、来源失败、上传待登录、云端待核对同时存在；状态相互独立。                       |
| 首次扫描已完成 | 返回 Telegram，可以启用/停用监控，看到游标对应时间和下一次检查时间；不运行真实定时扫描。         |
| 空内容库       | 各平台显示空态，保留来源、分享和收藏增量入口。                                                   |
| 本机空间不足   | B 站或夸克预览正常，提交下载显示空间不足，选择和清单保留。                                       |
| 执行程序不可用 | 可以浏览和选择，提交操作说明执行程序不可用。                                                     |
| 平台待登录     | 操作显示需登录，已浏览内容保留。                                                                 |
| 连接中断       | 顶部说明缓存状态可能过期，已有内容保留，写入被阻止；恢复默认场景后重新查询。                     |
| 预览版本冲突   | 提交下载时要求重新预览，不悄悄替换所选版本。此故障场景持续注入冲突，恢复默认场景后可走正常流程。 |

## 客户端与契约边界

- 页面只通过 src/api/client.ts 调用接口。默认 HTTP transport 使用 /api/v1，响应按 {data,requestId} / {error,requestId} 读取；只有显式 demo mode 才加载演示数据。
- 演示状态不会靠计时器自动变成成功。创建、预览和提交可立即返回替身结果；执行任务保持排队/示例状态，控制动作先记录意图。
- POST 发送 Idempotency-Key；更新来源、分享和任务动作提交 If-Match；真实兼容性仍需 Java 联调。
- 依据 [HTTP 语义契约](../contracts/HTTP-API.md)、[第一部分](../contracts/FEEDBACK-PART1.md)、[第二部分](../contracts/FEEDBACK-PART2.md)、[第三部分](../contracts/FEEDBACK-PART3.md) 冻结契约及 [产品规则](../docs/PRODUCT.md) 实现业务边界。媒体、目录、下载项目、上传队列和设置消费对应冻结模型；真实登录步骤与 Java/Go 进程联调仍需对应环境验收。
- 消费者字段问题已提交 [契约 #2](https://github.com/moonseries667/AllDownloads-v2/issues/2#issuecomment-6190960402)。不修改共同 contracts；生成式类型与真实接口接入在契约合入后跟进 [联调 #5](https://github.com/moonseries667/AllDownloads-v2/issues/5)。
- .env.example 给出隔离 Java 开发代理方式。真实 Java 联调和历史 demo 验收分别运行；浏览器不访问 Go 或平台业务接口。

## 第一部分反馈的复现方式

- 总览顶部读取 `overview.runtime` 的应运行服务与挂载事实。缺失字段、未知状态和接口失败均不会显示全部启动；演示环境始终明确标记。Bilibili 顶部将账号、刷新、下载数与归档数分开。
- Bilibili 默认最新视频，可切换标题正/逆序及最早视频。筛选和排序传给 Java，游标页完整读取后按每页六项呈现，排序不是仅重排当前页。发布时间未知排末；日期为上海时区起日包含、止日次日不包含。日历沿用 [Element Plus DatePicker](https://element-plus.org/en-US/component/date-picker.html)，支持清空和 Esc 焦点返回。
- 卡片正文/封面点击只加入选择；重复加入不重复。标题仅跳转，复选框、详情和下载按钮各自独立。全选固定当前筛选得到的内容 ID，之后刷新、切换筛选或来源不会扩大该范围。
- 来源保留实际身份，收藏夹、合集之外归在“其他 → 用户添加视频/电影/番剧”。打开管理来源，切换置顶会立即持久化；失败显示原因并重新读取持久状态，别名点击保存生效。
- 工作空间侧栏有独立滚动容器。在较矮窗口用 Tab 从“任务与问题”进入“设置与账号”，设置可滚动到可见区域，不依赖整页滚动。

媒体详情和下载清单已合入前端二提交 `01d3c89`，消费 Java 第一部分契约 `d508c7a`。生成类型与组件接口见 [数据接入说明](src/api/README.md)。详情 `saved` 只写会话选择，列表清单读取同一状态；改目录或改媒体会使旧预览失效，成功提交后下批恢复默认目标。第二部分由新对话完成，已在本分支接入，见下方第二部分集成说明。

## 第三部分集成与复现

第三部分前端二接入第一部分 `524e0fa`、第二部分 `bcd567b` 和第三部分下载管理 `d05539c`。共同契约为 Java 的 `baa03f5`（本分支接入提交 `46e9076`），并原样接入 `56a95f3` 的 OpenAPI projectIds 补全；本分支没有修改后台资格规则。`management.generated.ts` 从冻结 schema 生成；`archive-settings.ts` 负责上传/目录/设置适配，下载页使用前端一的 `api/download-management.ts`。

- `/archives`：只查询合格上传记录，未知进度不伪造百分比，传输 100% 仍显示上传中/核验中。暂停、继续、重试、核对仅按真实能力提供；无本机清理或删除数据操作。
- `/settings`：本机路径按钮触发运行主机的原生选择。取消/不可用保留原值；演示模式显示不打开系统窗口。Drive 点击“Goole Drive上传目录”，进入课程等子目录或返回根，选择后只是草稿，校验并保存才生效。重名目录使用稳定 ID，不按文字匹配；旧上传保持原目标。
- `/downloads`：默认替身包含 Bilibili 分 P、Telegram 音视频/照片/文档混合消息、夸克分享。取消混合消息中的照片后，其他文件仍可操作；运行中取消只保留意图，不靠定时器伪造停止。Bilibili 详情链接用精确 contentId 查询，跨批次分别展示。
- 共享 `DirectoryBrowser.vue` 来自第二部分目录选择器的视觉提取，夸克与 Drive 分别读取其目录 API，不共用账号或节点状态。

轻量上传交互参考 [Uppy Dashboard](https://uppy.io/docs/dashboard/) 的逐项进度与按能力操作，以及 [Element Plus Upload](https://element-plus.org/en-US/component/upload) 的明确列表状态；没有引入上传 SDK 或复制 Uppy 源码。许可来源为 [Uppy MIT](https://github.com/transloadit/uppy/blob/main/LICENSE) 和 [Element Plus MIT](https://github.com/element-plus/element-plus/blob/dev/LICENSE)，已有 Element Plus 依赖保留包内许可。
