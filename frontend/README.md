# AllDownloads 前端工作台

Issue [#3](https://github.com/moonseries667/AllDownloads-v2/issues/3) 的桌面纯前端实现，提供八个业务路由、隔离演示数据和统一 API 客户端。开发与本轮验证位于 Carbon；未部署到 Y7000P，未访问真实账号或平台。

## 本机运行

需要 Node.js 24，npm 依赖由 package-lock.json 固定。在 frontend 目录运行：

```powershell
npm ci
npm run dev
```

打开 [本机工作台](http://127.0.0.1:5173/)。服务只监听 127.0.0.1。演示数据保存在浏览器 localStorage 的 alldownloads.demo.feedback1.v2 键，刷新页面可保留模拟订单；设置页可恢复默认示例。浏览器内不会执行真实下载、转存、扫描、上传或磁盘清理。

```powershell
npm test
npm run build
npm run test:e2e
```

- npm test：非 watch 的 Vitest 业务边界测试。
- npm run build：vue-tsc 类型检查及 Vite 生产构建；输出 dist。
- npm run test:e2e：Playwright 使用本机已安装的 Chrome，无需登录态。在专用 5181 端口启动本工作树的开发服务，拒绝复用其他工作树服务。失败截图保存在被忽略的 test-results。
- TypeScript 固定为 5.9.3。实测当前 vue-tsc 3.3.13 无法读取 TypeScript 7 的 tsc 入口，因此没有采用不兼容组合。
- Element Plus 当前完整引入；构建有约 1 MB 未压缩公共块的体积提示。路由页面已分包，提示未被关闭。

## 异常场景验收

在“设置 → 前端验收场景”切换。切换前会确认重置本浏览器的演示记录；真实文件和账号不受影响。

| 场景           | 验证位置与结果                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 默认示例       | 未下载、部分完成、来源失败、上传待登录、云端待核对同时存在；状态相互独立。                       |
| 首次扫描已完成 | 返回 Telegram，可以启用/停用监控，看到游标对应时间和下一次检查时间；不运行真实定时扫描。         |
| 空内容库       | 各平台显示空态，保留来源/分享/链接入口。                                                         |
| 本机空间不足   | B 站或夸克预览正常，提交下载显示空间不足，选择和清单保留。                                       |
| 执行程序不可用 | 可以浏览和选择，提交操作说明执行程序不可用。                                                     |
| 平台待登录     | 操作显示需登录，已浏览内容保留。                                                                 |
| 连接中断       | 顶部说明缓存状态可能过期，已有内容保留，写入被阻止；恢复默认场景后重新查询。                     |
| 预览版本冲突   | 提交下载时要求重新预览，不悄悄替换所选版本。此故障场景持续注入冲突，恢复默认场景后可走正常流程。 |

页面中的“打开本机文件夹”在演示模式仅回显登记的相对位置；云端没有真实 URL 时禁用打开按钮。预览相对路径由 mock 传输层提供，页面不拼接权威下载位置。

## 客户端与契约边界

- 页面只通过 src/api/client.ts 调用接口。默认浏览器内 demo transport；HTTP transport 使用 /api/v1，响应按 {data,requestId} / {error,requestId} 读取。
- 演示状态不会靠计时器自动变成成功。创建、预览和提交可立即返回替身结果；执行任务保持排队/示例状态，控制动作先记录意图。
- POST 发送 Idempotency-Key；更新来源、分享和任务动作提交 If-Match；真实兼容性仍需 Java 联调。
- 依据 [HTTP 语义契约](../contracts/HTTP-API.md) 和 [产品规则](../docs/PRODUCT.md) 实现业务边界。overview、订单详情、preview summary、health、阶段记录、登录步骤等未冻结结构目前是本模块演示视图模型，不能当作正式 OpenAPI。
- 消费者字段问题已提交 [契约 #2](https://github.com/moonseries667/AllDownloads-v2/issues/2#issuecomment-6190960402)。不修改共同 contracts；生成式类型与真实接口接入在契约合入后跟进 [联调 #5](https://github.com/moonseries667/AllDownloads-v2/issues/5)。
- .env.example 给出隔离 Java 开发代理方式。切换 HTTP 模式仅连接明确配置的隔离实例，当前尚未验证真实后端；不访问 Go 或平台服务。
- mock 支持种子场景与主要错误分支，不是平台执行器，不提供真实恢复、速度或云端验证证据。

## 第一部分反馈的复现方式

- 总览顶部读取 `overview.runtime` 的应运行服务与挂载事实。缺失字段、未知状态和接口失败均不会显示全部启动；演示环境始终明确标记。Bilibili 顶部将账号、刷新、下载数与归档数分开。
- Bilibili 默认最新视频，可切换标题正/逆序及最早视频。筛选和排序传给 Java，游标页完整读取后按每页六项呈现，排序不是仅重排当前页。发布时间未知排末；日期为上海时区起日包含、止日次日不包含。日历沿用 [Element Plus DatePicker](https://element-plus.org/en-US/component/date-picker.html)，支持清空和 Esc 焦点返回。
- 卡片正文/封面点击只加入选择；重复加入不重复。标题仅跳转，复选框、详情和下载按钮各自独立。全选固定当前筛选得到的内容 ID，之后刷新、切换筛选或来源不会扩大该范围。
- 来源保留实际身份，收藏夹、合集之外归在“其他 → 用户添加视频/电影/番剧”。打开管理来源，切换置顶会立即持久化；失败显示原因并重新读取持久状态，别名点击保存生效。
- 工作空间侧栏有独立滚动容器。在较矮窗口用 Tab 从“任务与问题”进入“设置与账号”，设置可滚动到可见区域，不依赖整页滚动。

媒体详情和下载清单已合入前端二提交 `01d3c89`，消费 Java 第一部分契约 `d508c7a`。生成类型与组件接口见 [数据接入说明](src/api/README.md)。详情 `saved` 只写会话选择，列表清单读取同一状态；改目录或改媒体会使旧预览失效，成功提交后下批恢复默认目标。第二部分的 Telegram/夸克/通知升级由新的独立对话负责，不作为此分支第一部分成果。

## 验证范围与未完成验收

集成验证：46 项 Vitest 单测、vue-tsc 和生产构建通过；15 项受影响页面 Playwright 场景通过，包含四种排序与上海日期边界、跨页/跨来源选择、详情保存到提交的一致性、来源置顶及失败回退、日历焦点、侧栏滚动和既有夸克/清理/搜索流程。前端二提交还通过了 6 项独立媒体组件浏览器场景，涵盖空选/取消/多 P/剧集/语言/目录失效及完整可见的底部按钮。桌面路由和横向溢出检查覆盖原有六档尺寸；新增短窗口及 125%/150% 等效 CSS 视口（1152×576、960×480）检查。等效视口不冒充浏览器原生缩放或用户视觉验收。

Carbon 沙盒内 Playwright 能完成断言，但其 Windows 开发服务关闭挂起；同一测试经准确授权在桌面用户执行后正常退出。测试没有使用账号或执行平台媒体 I/O。

未完成：用户视觉验收、Java/Go 真实进程联调、Y7000P 部署、真实账号登录和平台 I/O、真实磁盘可写性、云端核对与七天持续运行。mock 的完成、下载、归档状态均为虚构事实，不据此关闭真实业务验收。
