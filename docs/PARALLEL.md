# 多对话开发安排

所有开发对话默认在 Carbon 分配给本任务的独立工作树内编辑、构建及隔离测试；主仓库为 D:\Code\Other\AllDownloads-v2。具体 Git 操作、任务状态与交接规则以 [Git 与项目协作指南](GIT-PROJECT-GUIDE.md) 为准。最终部署与正式运行统一落在 Y7000P，由协调对话组织；开发对话不得将 Carbon 当作正式后台主机，或将开发路径直接写入 Y7000P 运行配置。

## 1 对话与文件归属

推荐开前端、Java、Go 三个开发对话，由当前需求协调对话负责共同契约和最后集成。若只开前后端两个对话，后端对话负责 Java 与 Go 两个目录，仍保持它们的职责分离。

| 对话 | 可独立编辑的范围 | 主要交付 |
| --- | --- | --- |
| 前端 | `frontend/**` | 页面、客户端、契约 mock、前端测试 |
| Java 后端 | `backend/java/**` | 公共接口、领域规则、数据库、任务调度、Java 测试 |
| Go 执行 | `backend/go/**` | 平台适配器、传输、收据、执行协议、Go 测试 |
| 协调与集成 | `contracts/**`、`docs/**`、根目录配置、`scripts/**`、`tests/integration/**` | 规范冻结、共同构建入口、联调与端到端验收 |

开发对话不得同时编辑根锁文件、契约、项目规则或对方目录。契约问题先形成具体变更建议，由协调者统一修改；兼容新增字段也需通知消费者。默认一对话一工作树、一任务一分支，各自在自己的工作树提交并推送至同一仓库，协调者处理 PR 合并。共享工作树中的暂存与提交仍由协调者处理，不能在同一个工作树各自切换分支或操作暂存区。已在主目录进行的前端任务按指南中的衔接约定完成，不自动搬移或覆盖。

以下提示可以分别交给后续开发对话；同时附上准确的工作树路径、任务分支、Issue、契约基线提交和允许编辑范围。所有对话开工先读 docs/GIT-PROJECT-GUIDE.md，核对当前目录和分支，再执行各自提示。文件归属与契约先固定，再由用户选择开工方式。创建对话或向已有聊天发送指令按该动作的具体授权执行。

## 2 开发顺序

1. 协调者维护版本控制及目录归属，为新任务分配独立工作树、分支和可验收 Issue；Java 对话提出公共 OpenAPI 和 Go 操作类型规范草案，由协调者写入共同契约目录并审阅。前端同时可做页面骨架和基于现有语义的 mock，Go 可做私有执行器与文件恢复测试。
2. 冻结公共类型、错误码和 Java-Go 协议，完成一个替身下载操作从前端提交、Java 持久化、Go 执行到结果恢复的闭环。
3. 各自实现平台流程：B 站信息与手动下载；Tel 既有行为；夸克转存追更与选择下载。每个平台遵守同一任务机制，不另外建立独立业务队列。
4. 接入统一上传、云端核对和本机清理预览，完成错误场景。前端从 mock 切换到真实接口，核对字段和状态。
5. 在已授权条件下做 Y7000P 真实验收与持续运行；未验收的平台能力、远程部署和长时间结果明确列出。

任何阶段都不能用“先自动下载所有内容以后再加选择”代替 B 站和夸克的明确边界。禁止为了让界面看起来可用而假造后台完成状态。

## 3 前端对话开工提示

> 在协调者为本任务分配的 Carbon 独立工作树开发和构建前端，正式产物最终部署到 Y7000P。本机仅做开发与隔离测试。先读 AGENTS.md、README.md、docs/PRODUCT.md、docs/FRONTEND.md、contracts/HTTP-API.md 和 docs/ACCEPTANCE.md。仅编辑 frontend/**，不要改后端、共同契约或根配置。面向单人 Y7000P 桌面使用；B 站信息、下载、归档分离，只有用户提交才下载；Tel 保持既有收藏行为；夸克云盘转存追更与手动文件下载分离。先按共同契约用 mock 完成页面和异常状态，再接真实 Java 接口。遵循仓库当前已锁定前端版本；尚未建骨架时按前端需求建立。每次说明验证范围和接口阻塞，不编造后端能力。

## 4 Java 对话开工提示

> 在协调者为本任务分配的 Carbon 独立工作树开发和构建 Java 后端，正式程序及业务数据最终运行于 Y7000P。本机仅做开发与隔离测试。先读 AGENTS.md、README.md、docs/PRODUCT.md、docs/BACKEND.md、两份 contracts 文档和 docs/ACCEPTANCE.md。仅编辑 backend/java/**。Java 是公共接口、业务状态、数据库和调度的唯一所有者；不直接执行平台下载和外部工具。先提出 OpenAPI、操作请求和结果模型，交协调者统一落入 contracts/**，不得自行改变语义。实现持久任务、事务性阶段衔接、幂等、选择快照及恢复。B 站下载只能用户发起；夸克追更不能创建下载；Tel 按已核实行为实现。不迁移旧数据。先用 Go 替身验证正常、失败、重复和重启路径，再联调真实执行程序。

## 5 Go 对话开工提示

> 在协调者为本任务分配的 Carbon 独立工作树开发和构建 Go 执行程序，最终在 Y7000P 执行平台访问、下载和上传。本机仅做开发与隔离测试。先读 AGENTS.md、README.md、docs/PRODUCT.md、docs/BACKEND.md、contracts/RUNNER.md 和 docs/ACCEPTANCE.md。仅编辑 backend/go/**。Go 负责平台 I/O、认证会话、下载、文件处理、上传与核对，不读写 Java 业务数据库、不决定业务自动下载、不另起每个平台的业务后台。实现操作领取、租约、持久收据、幂等恢复、超时取消、平台适配器和受控外部工具。目录计划按 Java 契约执行并校验实际路径。先用本地替身与临时文件验证，真实账号和上传按当前任务授权执行；任何尚未验证能力明确报告。

## 6 共同完成标准

提交应描述完成的行为、执行过的检查、尚未完成的真实验收和需要协调的契约变更。每次交接同时提供工作树、分支、提交号、PR、推送状态及剩余未提交内容归属；任务进度记录在同一个 Issue，不在各对话分别维护相互矛盾的完成清单。不要将“代码已写”“mock 已过”“构建通过”“真实平台已过”和“七天稳定性已过”混为一项。

Carbon 只承担开发构建，Y7000P 承担最终部署、正式运行和真实验收。后续对话必须先核实主机、源码目录和部署目录；部署时只传递构建产物及配置模板，正式会话和运行数据在 Y7000P 建立。开工提示不自动授权安装系统服务、读取旧会话或处理旧数据。
