# 产品行为与目录规则

## 1 需求优先级

本文件以用户 2026 年 10 月 15 日的最新补充为最高优先级，覆盖早期方案中“夸克转存后自动下载”和“需要迁移旧数据”的描述。标为“设计默认”的内容是为完成方案作出的选择，后续调整须同步契约和验收。

已明确的范围：单人、Y7000P 本机、桌面浏览器；三个平台分别浏览；全局按标题或文件名搜索；列表突出主要信息，详情侧栏展示；下载和上传状态分别显示；不需要站内播放。首版必须包含合集批量下载、单视频及番剧下载、原有 Telegram 收藏处理、夸克转存追更及文件选择下载。

全新数据目录、全新记录、重新配置账号和来源，不迁移旧数据。旧文件、数据库、下载记录、未完成任务都不属于新版本的导入或清理对象。“不用管旧数据”不等于删除旧数据。

正式运行环境为 Y7000P。下文“本机成果”“本机根目录”“本机清理”均指 Y7000P，Carbon 仅负责开发构建和隔离测试。正式数据库、账号会话、媒体与缓存不放到 Carbon 开发目录中。

## 2 三个平台的自动化边界

| 平台 | 自动进行的事项 | 必须由用户主动发起的事项 |
| --- | --- | --- |
| Bilibili | 打开页面后刷新信息，维护已添加来源和元数据；完整下载成果进入归档队列 | 选择视频、分 P 或剧集并提交下载；重新下载或升级质量 |
| Telegram | 保持旧版收藏增量收录和音视频处理流程，按照已启用的收藏监控设置运行 | 首次登录、启用或暂停监控、手工补扫及失败处理 |
| 夸克 | 用户添加分享后转存；持续检查分享并将新增内容转存到指定夸克目录；刷新网盘文件信息 | 在网盘视图中选择具体文件或文件夹，提交下载 |

B 站信息刷新和夸克转存、追更，均不得隐式创建下载任务。已经提交的下载只包含提交时确认的文件版本与范围，后续新增内容不自动加入这次下载。

## 3 B 站信息 下载 存档

### 信息

来源支持自己的收藏夹、其他人的收藏夹、合集、单视频、番剧和电影。一次可粘贴多条链接，逐条显示识别结果。收藏夹、合集维护视频集合；番剧每季为独立内容单元、季内按集展示。导航“其他”分组包含“用户添加视频”“电影”“番剧”，分组不改变稳定来源身份与归档归属。支持来源别名与持久置顶。

新增来源收录全部可获取的历史信息；先显示已有信息，后台补齐并显示进度。打开页面触发刷新，同一来源的重复刷新合并；设计默认五分钟内复用最近结果，手工刷新可立即申请刷新，但仍服从平台等待要求。

视频卡片展示封面、标题、作者、时长、来源和状态。标题在新标签页打开 B 站；卡片其余非交互区域（包括封面）加入待选清单，尚不下载。信息按钮打开侧栏；不另设站内播放页。多 P 视频保持一个视频条目，分 P 低一级；合集与多 P 不混为同一层级。排序仅为标题正序/逆序、发布时间最新/最早，默认最新；日期区间以上海时区的视频发布时间为准。

同一视频为一条内容记录，拥有多个来源关系；各来源中都可找到，全部内容视图只显示一次。自己的收藏夹移除条目时同步移除该来源关系；他人的来源移除时保留信息并标记已移出。移除来源后保留已下载内容的资料、未结束任务以及其他来源仍引用的资料。完整刷新成功后才判断移出，刷新失败不能当作内容消失。

### 下载

必须存在一次用户下载操作。支持单项、跨页选择、筛选结果全选及排除项。多 P 可选部分，番剧可选季或集。提交前展示展开后的媒体数量、已存在项和统一目标目录。

设计默认：下载当前账号能够获取的最高音视频质量；多 P 单项下载默认全部 P，系列由确认面板显示具体所选集数。相同内容和质量不重复下载；再次下载或质量升级必须是明确动作。权限不足、付费不可看或地区限制保留原因，不声称能够绕过。

详情可保存具体视频、音频、各语言人工字幕与弹幕选择。未自定义时选择全部实际可下载项；明确空选择不能恢复全选。AI 或无法可靠分类的字幕不可选择。视频音频同选默认合并，单选分别输出，字幕/弹幕可独立选。保存只改变浏览器会话选择；预览与订单冻结资源版本、具体轨道、合并关系、质量、目录与归档策略，后续新增剧集和设置变化不扩大订单。去重依据为真实选择和目标，音频已完成不代表视频已完成。

长期只由主账号负责。旧双账号池不在 v2 建立，未迁移旧任务。2026 年 11 月的原计划不再成为新系统自动切换账号的定时任务。

### 存档

保存本机成果、元数据和云端位置，独立于来源是否仍然存在。媒体下载完成不代表云端存档完成。刷新标题或来源关系不能触发重新下载。

设计默认元数据基线：标题、简介、作者、原链接、平台标识、发布时间、时长、来源关系、分 P/剧集列表、实际质量、下载时间和文件清单；保存封面。能获取的字幕、弹幕和章节作为补充项保存，评论不默认采集。必要清单缺失阻止归档完成；补充项缺失显示警告并允许单独补齐。源站不提供与获取失败分别记录。

媒体和说明一起进入归档。首次下载确定实体归档来源，之后保持稳定；其他来源引用同一份归档记录，避免同一视频占用多份空间。用户主动重整目录另作显式操作，不能随刷新自动移动文件。

## 4 Telegram 保持原有收藏行为

保持收藏消息增量采集、音视频附件下载、消息文字与附件信息保存、重复检查、手动同步和自动监控。不要将“像之前一样”改造成新的手动挑选工作流，也不要扩大到聊天列表、频道订阅或发送消息。

网页内容区统一为“收藏夹”，按合格单消息或完整媒体组显示，展开时在省略正文原位置替换为完整文字。媒体下载进度与消息收录进度分别记录，附件失败可以补齐。必须包含音频或视频才纳入下载；纯文字、纯照片、纯普通文件以及照片加普通文件均跳过。合格单元的照片、音视频和其他实际附件一并下载，缩略图不当作用户照片。媒体组使用平台稳定组标识，跨页完整收集后再判定，不拼接相邻无关消息。

普通启动不自动访问 Telegram。用户点击“下载收藏增量”后，首次从消息 ID 1 扫描全部可访问收藏历史，并下载音视频 pending 项；以后从已保存游标之后继续，同时补处理 pending 项。首次扫描完成后可以显式启用默认六十秒的收藏监控，发现新增消息时执行同一同步及下载流程。监控开关与最后游标在新系统内持久保存，不导入旧游标。

Telegram 对外仅提供收藏夹增量下载，删除资源库和消息链接下载入口；旧消息链接提交返回 FEATURE_REMOVED，历史记录和可复用底层实现保留。收藏夹只展示符合资格的单元；跳过内容仍推进扫描，未完整组保留待核验，不能漏成员或重复下载。普通启动、首次同步、显式监控、取消和失败补齐语义保持。

本轮明确改变的是日期显示及目录中的日期段：`yyyy.MM.dd-HH.mm.ss`，例如 `2001.01.01-10.11.12`。这是日期时间格式示例，不是固定日期，也不是月份和分钟的相同含义。使用 `Asia/Shanghai` 显示，保存原始时间用于排序。

## 5 夸克网盘与下载

### 分享转存和更新

粘贴一条或多条分享链接，识别分享标识和提取码，选择夸克账号中的目标文件夹。可整批选择同一个文件夹，也可逐条指定。每条分享分别记录完整分享标识、目标目录、转存结果和最近更新结果。

目标只能选择真实文件夹，不接受手填路径。根显示“我的云盘”，目录项只显示自身名字，展示路径由真实父链用 `/` 连接。统一/逐条模式均在提交时固定每条分享的节点标识和版本；失效、移动或权限变化必须明确处理，不退回其他目录。云盘转存目标与下载清单的本批本机目标完全独立。

转存成功即进入网盘目录维护。设计默认每小时检查一次分享更新，也支持手动检查；遵守平台等待时间，同一分享不能并发检查。新增文件自动转存到原目标目录。原分享删除文件时不删除已转存副本；同名内容发生变化时保留旧版本并记录差异，不覆盖已下载成果。

目标网盘目录被移动、删除或失去权限时暂停该分享更新并说明原因，不能转存到猜测的替代位置。分享失效后保留已有网盘文件和下载记录。

### 网盘选择下载

网盘视图提供目录树、面包屑、文件名、类型、大小、更新时间及本地下载状态。支持多选文件、选择文件夹及跨目录选择；下载前由后端展开为确定的文件清单。选择的文件夹后来有新增文件，不扩大本次下载范围。

首版下载对象是本应用转存并管理的分享目录及其后代节点。目标目录选择器可以浏览该账号的其他目录；未关联分享的任意网盘文件不自动获得虚构的分享标识或本机目录。这样每次下载都能确定 `Quark/分享后缀/内容` 的归属。

转存和下载分别有状态、按钮和任务。转存完成、追更完成、打开网盘页面都不能自动开始下载。下载成功不删除夸克网盘中的副本。

## 6 统一下载目录

全局只配置一处 `downloadRoot`，必须是 Y7000P 本机的真实可写目录。它是用户文件的默认根目录，不能使用 Google Drive 挂载盘或 UNC 网络目录充当本机暂存。第一部分新增：用户可在本批下载清单覆盖本机目标，经 Java 建立受控目标、Go 核验真实范围与可写性后使用；该批次固定 `archivePolicy=NONE`，重试、重启与结果重放均不自动归档。覆盖不修改全局根，下批未指定目标恢复默认规则；更改选择或目标需要重新预览，提交只引用已展示的快照。浏览器本地文件选择权限不能代替运行主机目录校验。

独立配置 `archiveDestination` 表示 Google Drive 目标位置。两者名称、用途和状态分别显示，不存在三个平台各自一份 Downloads 配置。

| 类型 | downloadRoot 下的相对路径 |
| --- | --- |
| B 站收藏夹 | `Bilibili/来源名称(收藏夹)/标题(实际BV标识)/` |
| B 站合集 | `Bilibili/来源名称(合集)/标题(实际BV标识)/` |
| B 站单独视频 | `Bilibili/用户添加视频(用户添加)/标题(实际BV标识)/` |
| B 站多 P | 内容目录后追加 `P01-副标题`，无副标题仅 `P01`，支持超过 99 P |
| B 站番剧 | `Bilibili/来源名称(番剧)/季标题(实际季标识)/实际集副标题/`；无副标题为 `第01集(实际集标识)` |
| B 站电影 | `Bilibili/来源名称(电影)/电影标题(实际标识)/实际语言版本标题/`；单版本无多余 P 层 |
| Telegram | `Telegram/<批次时间 yyyy.MM.dd-HH.mm.ss>/<消息ID>/<安全化原文件名>` |
| 夸克 | `Quark/<shareFolderKey>/<相对分享根的文件或子目录>` |

夸克目录规则的具体解释：设计默认 `shareFolderKey` 取规范化分享标识末尾八个字符。分享标识可能含字母，保留原字符，不仅抽取数字；不把查询参数、提取码、尾斜杠当作分享标识。例：分享标识 `abcd12345678` 对应 `Quark/12345678/课程/第一课.mp4`。不额外加分享标题、转存目录名称或下载日期层级。

后八位不足八位时使用完整标识；不同分享后缀撞名时，对新分享逐步向左增加字符直至唯一，已分配目录保持不变。Windows 大小写不敏感冲突也需检查。完整标识才是去重依据，短后缀仅用于目录展示；同一分享重试或更新沿用原目录键。

Telegram 收藏同步沿用旧版批次语义：本批新增消息按消息时间、再按消息 ID 排序，最早者的消息时间确定批次目录，同批目标媒体共用该目录。手工链接按每个独立资源帖或媒体组内最早相关收藏成员的消息时间决定，无收藏成员时用该组最早成员时间；一次提交多条跨日期链接不会把所有资源放进整批最早日期。同组多链接及重复提交复用已有资源目录，不使用实际下载时间。

示例 `Telegram/2001.01.01-10.11.12/123456/音频.mp3`。相同批次重试复用原目录；不同收藏批次恰好同秒时在日期段后追加 ` (2)` 等序号，日期主体格式不变。每个附件各有一个同级侧车，完整文件名后追加 `.metadata.json`，例如 `音频.mp3.metadata.json`，多附件不共用一个覆盖式侧车。消息 ID 层和必要的文件名序号防止同名覆盖。原始消息时间不可取得时显示待处理，不编造时间。

临时分片放入 `downloadRoot/.work/<操作标识>/`，完成并验证后进入最终相对目录。`.work` 不被上传或显示为已下载。Google Drive 使用与成品相同的相对层级。

目录根修改须先暂停新调度并处理在途任务；每个已接收任务绑定明确的根目录版本，不能运行中悄悄改目的地。旧根已有文件不会因设置改变被自动搬迁或删除。

上述 Bilibili 括号统一为英文 `()`，标识保留平台真实大小写，不伪造 BV。Java 持久分配安全化目录与碰撞后缀；刷新标题、来源或导航分组不能自动移动已有成品。来源目录暂按“来源名称(来源类型)”解释。

## 7 上传 留存与异常

设计默认完整成果自动进入独立的上传队列，可分别暂停下载与上传；用户覆盖本批目录的 `NONE` 订单除外。Google Drive 实际结果核对完成后才标记归档完成。挂载成功、本机下载完成、云端核验归档是独立事实。上传失败保留本机文件，重新上传不能重新触发平台下载或夸克转存。

本机清理默认手动，只有已验证云端完整的本应用成品可进入清理候选。需要预览清理清单和占用空间；不能包含原始人工文件、旧版数据和其他路径。源站删除、网盘更新与本机清理都不联动删除云端归档。

关闭网页不停止已提交任务。重启后保留暂停状态，恢复未完成阶段。暂时故障有有限重试和下一次尝试时间；登录、空间、权限、内容失效等需要处理的情况明确提示。错误至少说明阶段、对象、已完成事项和下一步操作。一个平台的问题不能阻塞其他平台浏览和独立任务。

所有非成功提示可在顶部通知的“需要关注”中查看。点击弹窗本体仅关闭该次提示，已读也不解决业务问题；后台持久错误在刷新后仍能恢复。同任务同错误使用稳定身份更新，任务实际成功后才解决对应错误，未解决警告仍保留。
