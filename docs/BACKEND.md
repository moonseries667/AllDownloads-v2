# 后端职责与稳定性要求

## 1 技术与职责决策

采用 Java 业务应用与 Go 执行程序两个自有常驻程序。Java 使用 Java 21 LTS、Spring Boot 稳定版和 JDBC；Go 使用仍受官方支持的稳定版本。实际补丁版本、构建工具与依赖在首次建骨架时统一锁定，禁止使用浮动 latest 或预览版本作为可复现构建依据。

首版使用本机 SQLite 业务数据库，由 Java 独占业务写入；采用 WAL、短事务、写操作串行协调、有限 busy 等待和正确备份。Go 的执行收据属于独立私有日志，不连接 Java 业务数据库。当前单人规模不引入 Redis、消息代理或外部数据库服务。

| 职责 | Java 唯一负责 | Go 唯一负责 |
| --- | --- | --- |
| 浏览器接口 | 公共 HTTP 接口、查询、参数校验、分页、通知 | 不暴露第二套浏览器业务接口 |
| 产品行为 | B 站用户触发、夸克转存追更与下载分离、Tel 策略 | 执行指定操作，不自行推导新的业务任务 |
| 资料目录 | 来源、视频、消息、网盘节点及版本、归档关系 | 获取平台信息，返回规范化快照和完成标记 |
| 调度 | 持久任务、依赖、重试时机、优先级、并发配额 | 领取已批准操作，执行受控并发与取消 |
| 账号 | 账号称呼、能力、状态、登录流程的公共入口 | 平台认证过程、私有会话存储、凭据实际使用 |
| 路径 | 唯一目录规则、目标映射与任务目录版本 | 验证并实际写入文件，拒绝越界路径 |
| 传输 | 选择范围、完成规则、归档策略 | 下载、续传、校验、封装、上传、云端核对 |
| 任务事实 | 接收事实后事务性更新业务状态 | 持久执行收据、实际字节数、文件清单、错误原因 |

业务复杂性集中在 Java，平台和文件 I/O 复杂性集中在 Go。这是职责划分，不表示 Java 天生不会出错或 Go 能保证网络稳定。不得按“B 站 Java，Telegram Go，夸克另写一套”的方式形成三套任务系统。

## 2 运行和目录

前后端源码、构建及开发服务器独立。Carbon 仅负责开发、构建和隔离测试，开发时浏览器通过前端代理访问隔离的 Java 测试实例或 mock。最终前端发布产物、Java 和 Go 均部署到 Y7000P；正式前端静态文件可由该机 Java 分发，不要求 Node 常驻。正式 Java 与 Go 在 Y7000P 内通过受保护的回环 HTTP 通信，公共接口默认仅监听 Y7000P 本机，Go 不接收浏览器跨域请求。

```text
frontend/                  前端源码与 mock
backend/java/              Java 应用
backend/go/                Go 执行程序
contracts/                 共同契约与后续机器可读规范
tests/integration/         跨进程验收
scripts/                   统一启动、停止、构建脚本
runtime/control/           Java 数据库及运行记录，不进入 Git
runtime/runner/            Go 执行收据及私有运行记录，不进入 Git
runtime/auth/              用户完成登录后生成的私有会话，不进入 Git
```

上述 runtime 结构在正式运行时属于 Y7000P 部署目录；Carbon 只使用独立且可重建的测试运行目录。构建应以 Y7000P 的实际 Windows 系统和架构为目标，交付前端静态文件、Java 应用、Go 程序及明确版本的必要工具；不能依赖 Carbon 已安装的软件或共享路径才能启动。发布包排除账号会话、业务数据库、下载缓存和测试数据。

Y7000P 的部署目录、运行账户、Java/工具运行时位置、下载根与云端位置在部署或首次设置时确定，不硬编码开发电脑绝对路径。初次启动验证配置完整性、目录实际可写性、剩余空间、Go 能力及必要工具版本。检查不通过时给出具体项目，保留资料浏览能力。

统一启动入口只启动声明的 Java、Go 程序及必要受控子进程；退出时有界等待并记录未完成操作。一个数据目录只允许一个 Java 主进程和一个 Go 执行实例。端口或实例锁冲突明确失败，不能自动开第二份运行。系统服务或开机任务的安装属于后续部署动作，本次需求交付不执行。

## 3 业务模型

| 对象 | 标识与关系 | 关键规则 |
| --- | --- | --- |
| Source | 平台、账号、类型、平台来源标识 | B 站信息来源；不能以来源存在推定自动下载 |
| MediaItem / MediaPart | 平台稳定标识及分 P/剧集标识 | 信息、媒体部分、来源关系独立 |
| SavedMessage / Attachment | 账号与收藏消息标识、附件标识 | 文字与附件关联，收录游标和下载状态独立 |
| QuarkShare | 完整分享标识、账号、目标云盘目录 | 追更状态与任何下载状态独立 |
| CloudNode / NodeVersion | 账号、网盘节点标识、版本依据 | 文件夹层级和文件版本可追踪 |
| Selection | 不可变的用户选择快照 | 记录具体媒体部分或文件版本，不随来源更新扩大 |
| DownloadOrder / Task / Operation | 用户请求、可见任务、可恢复执行步骤 | 一个订单可包含多个文件；操作是重试单位 |
| Artifact / ArchiveRecord | 成品文件清单及本机、云端位置 | 文件存在、本机完成和云端核对分别记录 |

ID 对外统一为不透明字符串；平台大整数也序列化为字符串，前端不得用浮点数处理。数据库用唯一约束保证来源引用、文件版本和未完成重复请求不会生成重复业务对象。

状态更新与下一阶段任务生成必须处于同一数据库事务。媒体下载成功后先进入成果整理与验证；只有 Artifact 最终化和必要信息验证成功的事实确认，才与“待上传操作”入队一起提交。提交失败不能出现网页显示成品就绪但上传任务丢失。

## 4 B 站处理规则

信息收录、用户下载订单、存档记录为三个独立模块。信息刷新入口无权调用下载创建逻辑。下载创建必须带 `trigger=USER`、选择快照和请求幂等键；禁止定时器伪造用户触发。

信息刷新先写入新的快照批次，只有遍历完整成功后才能发布来源成员变动。失败快照不触发删除。跨来源根据平台稳定标识合并媒体，来源关系单独保存；失效项目仍保留能够获取的资料。

下载前确认实际可获取的分 P、剧集和质量；单独下载某部分不能错误地标记全部内容完成。质量策略、来源目录和所选范围在提交时固化。相同内容的其他来源只增加归属，不重新生成同质量文件。

Java 制定必要元数据清单并判断存档完整性；Go 获取媒体和补充资料、执行必要封装，返回实际结果。无字幕、无弹幕、权限限制和网络失败是不同结果。账号不可用暂停受影响操作，不能让整个目录不可浏览。

所有宣称支持的来源类型必须用真实可访问内容完成一次信息、选择、下载和归档链路验收。某一类型未通过时明确标注实现缺口，不能用普通视频成功替代番剧、电影或多 P 验收。

## 5 Telegram 处理规则

保留原有 Saved Messages 收录与下载语义，原代码只能作为行为参考，不作为 v2 运行依赖。用户要求不迁移数据，因此新实例自行建立账号、监控参数和游标。

普通启动不访问 Telegram；用户首次点击收藏同步从 ID 1 扫描全部可访问历史，以后从 cursor+1 开始。第二部分更新：扫描保留全部类型事实，完整单消息或平台媒体组至少含一个由 MIME/明确媒体属性确认的音视频才入队，合格单元全部实际附件含照片、普通文件一起下载。纯文字/照片/文档跳过并推进游标，未完整组阻止越过其最早成员。标签、扩展名和文案不作为资格依据。

首次完整扫描之后可显式启用默认六十秒的监控，发现较大消息 ID 后执行收藏同步。已有收藏任务活动时合并/跳过本次检查，不积累重复任务。对外仅保留收藏夹增量下载，消息链接下载入口关闭，手动下载预览不得接纳 Telegram 附件以绕过资格。补齐未完成文件和逐附件元数据保持，完整音视频不能代替未完成照片或侧车。

时间目录保留旧版批次时间依据，改成 `yyyy.MM.dd-HH.mm.ss`，时区固定 Asia/Shanghai，具体路径见产品规则。不能用下载时间、机器时区或每个文件单独的时间替换收藏批次语义。

侧车元数据保留原有用户可见信息：channel、author_tags、source_links、message_id、original_file_name、media_type、expected_size、message_url、message_preview、local_path、size、downloaded_at、status。message_preview 包含文字、消息时间、发送者和来源；原先 schema 2 作为信息基线，v2 可以有新 schemaVersion，不承担旧 schema 导入兼容。包含正文的侧车是归档内容，不是普通日志。

媒体下载可复用经版本锁定的 Go 工具 tdl，由 Go 包装为受控执行适配器。必须使用结构化导出或已验证的输出契约，不能解析本地化终端提示来猜测成功；先验证版本、退出码和结果清单。禁止 Go 再启动 Python 包装 tdl。

消息收录事务先保存消息、附件与对应待处理动作，再推进扫描游标。已经收录但未下载的附件仍在队列中；进程崩溃或单附件失败不会变成漏项。重复扫描不重复下载已验证完整的附件。

## 6 夸克处理规则

分享、夸克目录、网盘文件版本、下载订单是不同对象。分享新增和更新只创建解析、转存、核对与目录刷新操作；禁止在这些结果处理器中创建下载订单。

定时更新由 Java 统一管理，默认一小时一次；用户手动检查合并到同一分享已有的检查任务。Go 根据真实平台结果返回新增、变化、失效和未知项目，Java 决定下次运行与页面状态。

转存接口超时可能已经产生云盘副本，必须先按已保存的意图、平台标识和目标目录核对结果，再决定是否继续。不能无条件重发转存请求。核对不能确定时进入 `RESULT_UNKNOWN`，保留现有文件，提供重新核对入口。

网盘选择以真实节点标识和版本为依据。文件夹下载由后端展开快照；树的懒加载状态不影响选择完整性。下载前节点消失或版本变化时返回明确变更，要求重新预览该选择，不能改下另一个同名文件。

目录选择器提供真实根、父节点、名称、版本、可选性及权限事实；展示路径由父链生成，根标签“我的云盘”不进入 path。统一/逐条模式均提交每条目标 ID 与 revision 并冻结映射。转存只使用云盘目标，下载复用公共预览/订单的本机目标和 NONE 不归档策略；更新和转存不创建本机订单。

追更新增文件允许自动转存，不允许自动下载；原分享删除不删除已转存副本。同名变化以文件版本与稳定标识判断，不能只看名称和大小。无法可靠判断时标记待核对，不覆盖现有归档。

## 7 下载 文件和上传

Java 生成唯一的目录计划和 `storageRevision`，Go 接受逻辑根标识与相对目录，校验实际解析后的路径仍在配置根内。路径计算规则归 Java；Go 的重复检查只负责执行安全，不能产生另一套命名或回退目录。

目录必须覆盖中文、长文件名、同名、Windows 保留名称、尾空格、大小写不敏感及符号链接等情况。路径非法时先返回有解释的校验问题，不能在运行时悄悄退回历史 Downloads 或云盘挂载目录。

下载先写本机 `.work`，按文件验证长度、可用的平台校验依据和媒体基本可读性，确认关闭文件句柄后再发布成品。发布要能恢复：崩溃发生在文件就位与业务确认之间时，根据执行收据与成品身份核对，不重下、不盲目覆盖。不得依赖跨卷重命名或硬链接作为唯一发布方式。

HTTP 分片续传必须确认资源版本、范围响应和总长度；服务不支持续传时只重下受影响文件，明确记录原因。文件名相同不代表内容相同。已完成文件的校验结果和生成它的操作标识应可追踪。

FFmpeg/ffprobe 允许作为 Go 管理的有界子进程。上传可复用锁定版本的 rclone Go 可执行工具；直接调用云端对象传输及核对，不把挂载缓存写入成功当作云端成功。工具的配置和认证通过私有文件或受控输入使用，不把凭据写在命令参数和日志里。

上传按固定的 Artifact 清单进行。云端核对数量、名称、大小和可取得的校验值；缺少必要核对依据时采用明确的更强检查或停在待核对，不能默认为一致。新文件未核对完成前保留旧的可用版本。已有云端文件需要与清单对应，不能因为重试生成同名重复对象。

## 8 持久任务和并发

Java 数据库保存任务、依赖、操作请求、下一次尝试时间、暂停状态和最后确认结果。内存线程池只用于执行，不作为唯一队列。Go 通过内部协议领取操作，收到 Java 的持久化确认后才删除可清理的结果收据。

任务状态：`QUEUED`、`RUNNING`、`PAUSING`、`PAUSED`、`WAITING_RETRY`、`NEEDS_ACTION`、`SUCCEEDED`、`FAILED`、`CANCELLED`。批次可以显示聚合 `PARTIAL`，不能把部分文件成功解释为整批成功。取消或暂停请求先记录意图，执行者实际停止并确认后才变成最终状态。

设计默认全局两个下载文件同时执行、一个上传文件同时执行；一个账号同一时刻只有一个会话修改或转存操作。平台明确要求更低并发时降低。每个最终文件路径只有一个写入者。任务按平台公平轮转和提交顺序调度，用户可提高优先级。

刷新、下载、转存、上传使用不同的容量预算，长文件下载不能阻塞目录浏览。大文件流式处理，禁止整体载入内存。所有网络操作、平台等待、子进程和数据库锁等待都有可观测期限。

Java 负责业务重试时机，设计默认临时错误在 30 秒、2 分钟、10 分钟后至多自动重试三次，平台 Retry-After 或限流等待优先。登录、权限、空间和失效内容直接等待处理；有副作用的请求结果不明时先核对，不套用普通重试。

Go 可以在同一次操作内做有限的无副作用网络重试，但不能再建立独立业务重试循环。重试耗尽显示原因和人工入口，不永久高速重试。任务恢复及租约规范见 [执行协议](../contracts/RUNNER.md)。

## 9 认证 配置和可观测性

账号私有会话由 Go 的平台适配器维护，Java 只保存不透明引用及账号状态；公开接口不能返回原始 Cookie、token、会话文件和带秘密的下载地址。登录由用户完成官方支持的授权步骤，成功后返回账号称呼和能力。诊断输出脱敏，不记录消息正文或凭据作为常规日志。

前端的本机访问与 Java-Go 内部访问分别校验来源和会话；开发代理的允许来源明确，不用任意来源通配。内部凭据自动生成并存放在受限运行目录，不写入仓库。浏览器不能调用内部租约接口。

一个统一设置入口管理下载根、云端目标、时区、并发和监控。配置带版本，已接收任务绑定相应版本。对根目录和账号的变更预先检查影响，不能让同一任务用前半段旧配置、后半段新配置。

记录 taskId、operationId、attempt、platform、阶段、错误码、已确认字节数及时间；关联信息足以追踪一次下载到归档。健康状态区分 Java、Go、账号和存储；Go 不可用时 Java 仍提供已有资料及清楚的不可用原因。

后台问题使用任务/对象与错误码的稳定身份持久保存，重复报告更新同一项；GET /issues 默认返回未解决 ERROR/WARNING。acknowledge 只置已读，不更改任务、不重试、不解决；任务真正成功才解决对应错误。公开原因使用受控文本，不把原始平台错误或堆栈返回前端。

## 10 检查与工程交付

Java：目录命名、用户触发校验、选择快照、状态迁移、去重约束、数据库事务和重启恢复测试。使用生产同类型 SQLite，不能只用内存集合或其他数据库代替事务行为。

Go：平台适配器契约、HTTP 范围/版本变化、超时/取消、部分文件恢复、重复操作收据、工具异常退出及 Windows 文件发布测试；对相关并发模块运行 race 检查。平台 I/O 先使用本地替身验证，再做已授权的真实端到端验收。

跨进程：断开结果响应、重复上报、旧租约、进程重启、账号失效、文件系统错误、云端核对失败。已有测试不能以 mock 成功替代真实平台验收。至少连续运行七天并执行指定故障场景后，才能声称稳定性达到验收基线。

依赖、工具版本、配置模板和构建入口均纳入版本控制；运行数据与凭据排除。不得为了通过构建安装共享运行时、关闭安全检查、读取旧账号会话或改旧项目服务。

## 11 决策依据

- [Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)：核对 Java 兼容范围，不能把兼容性当作项目稳定性证明。
- [Spring JDBC](https://docs.spring.io/spring-framework/reference/data-access/jdbc.html)：使用清楚的数据库访问和事务职责。
- [SQLite WAL](https://sqlite.org/wal.html)：支持读写并发但同时只有一个写入者，因此业务写入集中到 Java，并使用本机文件系统。
