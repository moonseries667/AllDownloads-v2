# Y7000P Windows 发布与运行

Carbon 只构建和做隔离验证，正式运行在 Y7000P（`LAPTOP-ENFQAOT8`）的 Admin 桌面会话。部署根默认是新的 `D:\Code\Other\AllDownloads-v2`，可以用 `-Root` 改为另一个新目录。旧 `D:\Code\Other\AllDownload` 的文件、会话、数据库和服务完全保留；脚本拒绝以该目录或其子目录为目标。

这套入口不注册服务、计划任务或启动项，不修改防火墙、代理、系统 PATH 或执行策略。安装仅落盘，启动须由用户在 Admin 桌面中显式执行。SSH 安装不等于桌面启动；协调者负责远程传输、安装与实际验收。

## 布局与产物

```text
D:\Code\Other\AllDownloads-v2\
  app\current.json                    当前版本指针，无凭据
  app\releases\<version>\
    release.json                      源码提交、版本与工具锁
    backend.jar                       Spring Boot 可执行 jar
    runner.exe                        正式 Go cmd/runner
    session-setup.exe                 按需交互配置新 Telegram/夸克会话
    frontend\                         生产 dist，同源 HTTP 模式
    config-templates\                 无凭据结构示例
  scripts\release\                    安装、启动、状态与停止入口
  tools\ffmpeg-9.0.2\                 ffmpeg.exe、ffprobe.exe
  tools\tdl-0.20.4\                   tdl.exe
  runtime\config\                     私有配置及生成的 launch.properties
  runtime\auth\                       新 v2 内部 token、新账号会话
  runtime\control\                    Java 唯一业务数据库
  runtime\runner\                     Go 状态与执行收据
  runtime\processes\                  本部署 PID、启动时间、执行文件与锁
  runtime\logs\                       每次启动独立的 stdout/stderr
  downloads\                          默认统一下载根
```

发布包只收集 Java jar、经过 `-trimpath` 的 Windows amd64 正式 runner 与 session-setup、前端 dist、明确列出的三个工具可执行文件、发布脚本、模板和本说明。不会复制源码目录、工具整目录、测试数据库、媒体、账号会话或 Carbon 配置。源码映射与含 Carbon 绝对路径的前端文本会被拒绝。不要把 `runtime` 或 `downloads` 放进发布包，也不要把业务目录加入 Git。

## 在 Carbon 构建

需要 Java 21、项目 `go.mod` 指定的 Go、Node 24/npm，以及已准备好的 **FFmpeg/ffprobe 9.0.2** 和 **tdl 0.20.4**。Y7000P 现有 FFmpeg 8.1.2/N122209 不满足产品锁，脚本不会退回系统版本；三个工具只复制到项目内。Java/Node 不被打包或安装，Y7000P 已有 Java 21；正式运行无需 Node。

在已提交模块源码的工作树执行；以下工具路径替换为 Carbon 上实际路径，不会写入产品配置：

```powershell
Set-Location '<源码工作树>'
.\scripts\release\Build-WindowsBundle.ps1 `
  -Version '2026.10.16.1' `
  -JavaHome '<Java21目录>' -GoExecutable '<Go目录>\bin\go.exe' `
  -FFmpegDirectory '<FFmpeg9.0.2目录>\bin' -TdlExecutable '<tdl0.20.4目录>\tdl.exe'
```

默认依次执行 Maven package（不重复模块测试）、正式 Go 构建、`npm ci` 和生产前端构建。npm 首先使用 npmmirror，失败只向官方源重试一次，仍保留锁文件校验。前端强制 `VITE_API_MODE=http`、`VITE_API_BASE=/api/v1`。构建产生 `dist/AllDownloads-v2-<version>-windows-x64/` 和同名 zip，输出版本已存在时拒绝覆盖；`-NoArchive` 只生成目录。

协调者已有构建产物时可传 `-UsePrebuilt -JavaJar <jar> -RunnerExecutable <runner.exe> -SessionSetupExecutable <session-setup.exe> -FrontendDirectory <dist>`；仍会核对两个 Go 产物的生产命令、Windows amd64 与 trimpath、jar 主类和工具版本。默认构建依赖集成后的 `cmd/session-setup`。预构建前端必须来自上述两个环境变量的生产构建，并在该 dist 中写入 `release-build.json`：`{"apiMode":"http","apiBase":"/api/v1"}`。该文件是构建者记录，不能证明来源不明的 dist 正确；不要为演示产物伪造标记。组包不能代替模块测试。

## 在 Y7000P 安装与启动

把包传到 Y7000P 的新暂存目录并解压，先核对实际主机。安装不启动进程，已有私有配置、token、工具和已安装版本不会覆盖。`-JavaExecutable` 可给 Java 21 的绝对路径，首次写入 `deployment.local.json` 后由该私有文件控制；`-Port` 同样只初始化一次。

```powershell
# Y7000P；<解压目录> 内直接包含 release、scripts、tools。
& '<解压目录>\scripts\release\Install-WindowsBundle.ps1' `
  -BundleRoot '<解压目录>' -Root 'D:\Code\Other\AllDownloads-v2' `
  -JavaExecutable '<Java21目录>\bin\java.exe' -Port 8080

# 在已登录 Admin 的桌面 PowerShell 显式执行。
& 'D:\Code\Other\AllDownloads-v2\scripts\release\Start-AllDownloads.ps1'
& 'D:\Code\Other\AllDownloads-v2\scripts\release\Get-AllDownloadsStatus.ps1'
```

首次安装生成新内部 token，不显示其值，也不读取旧凭据。`runner.local.json` 初始为空账号配置，启动不访问 Telegram 收藏或导入旧会话。B 站只允许一个主账号 `bilibili-main`，不建立双账号池、轮换或定时切换。账号页的检查和登录由 `CHECK_ACCOUNT` / `AUTH_STEP` 在用户操作后执行；普通状态查询不访问平台。Telegram/夸克缺少新会话、Drive 缺少新 Desktop OAuth client 配置时须显示本机配置步骤，不把空配置当作已登录。Go 配置字段以集成后的 [Go 说明](../backend/go/README.md) 为准。模板中的 `<ROOT>` 仅解释结构，安装会按实际根路径自动生成可用路径。

`session-setup.exe` 只供用户在 Y7000P 交互终端按需建立新 Telegram QR 会话或隐藏输入新夸克 Cookie；入口参数以该程序 `-help` 和集成后的 Go 说明为准。它不随 Start 自动运行，不读取旧会话，不把 Cookie 或 token 写进命令参数。首次登录前由用户核对新 v2 runtime 目标。

Java 固定监听 `127.0.0.1`，Go 只访问同机 Java，没有独立公共端口。Java 通过 `alldownloads.frontend-root=<release>/frontend` 提供静态前端和 SPA 深路由，API/internal 错误不回退首页。启动先检查端口未占用、准确工具版本与配置，再依次等待 Java HTTP、Go 注册能力、首页及 `/settings` 深路由，最后才报告 `RUNNING`。界面、账号权限与真实下载仍需另行验收。

默认下载根为 `<Root>\downloads`。如要使用另一个明确授权的新根，停止后修改 `runtime/config/runner.local.json` 中 `allowedRoots`、`roots.download-root`，并先创建目标目录；Java 使用同一根。不要指向旧版媒体目录。改变端口时须同步修改 `deployment.local.json.port` 和 `runner.local.json.controlUrl`。已有配置不随重装自动更新。

## 停止、诊断与版本回退

```powershell
& 'D:\Code\Other\AllDownloads-v2\scripts\release\Stop-AllDownloads.ps1'
```

停止只使用 `runtime/processes/active.json` 记录的两个 PID，并核对启动时间和执行文件路径，避免 PID 复用。没有记录、进程已退出或身份不匹配时不搜索全机进程。不会运行 `taskkill /IM java.exe`，不会停止旧应用。当前停止是进程终止，进行中的任务按产品租约和收据恢复规则对账；需要暂停业务时先在页面暂停任务。日志、数据库、配置和媒体都保留。

启动失败会停止本次已经登记的进程，留下 `START_FAILED` 状态和本次日志。查看 `runtime/logs/<启动时间>-java.stderr.log`、Java stdout 和 runner stderr；日志目录路径会显示在错误信息中。端口被其他进程占用时失败退出，不停止占用方。锁冲突时等待另一个生命周期入口结束；状态入口返回 1 表示未确认双进程健康。脚本不输出私有配置或 token；人工分享日志前自行移除可能的账号/业务内容。

升级前先停止当前部署，再以新版本安装；旧 release 不删除，新版本全部复制和检查成功后才切换指针。安装失败若已留下未激活版本目录，保留现场，核对后用新版本重试；不要批量清理。回退时保持停止状态，确认目标版本兼容当前 v2 数据库，然后把 `app/current.json` 的 `version` 改为保留的旧版本再启动。脚本不回滚数据库、不恢复旧 AllDownload 数据，也不声称跨 schema 回退安全。

## 验证范围

在 Windows 的源码工作树运行 `scripts/release/tests/Test-WindowsRelease.ps1`。测试只使用独立临时目录和本地替身进程，验证新目录安装、私有配置保留、生命周期锁、PID 身份核对、启动失败清理和健康检查条件；不会访问真实平台、旧应用或 Y7000P。构建检查与本地替身通过均不等于 Y7000P 部署、Admin 桌面目录弹窗、真实账号下载上传或七天运行通过。正式验收由协调者对照 [验收标准](ACCEPTANCE.md) 记录。
