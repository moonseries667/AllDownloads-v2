# 交付验收

## 1 验收顺序

Carbon 仅进行开发构建和基于不含真实账号的 fixture 的隔离验证，包括契约、事务、临时文件及故障路径。构建产物最终部署到 Y7000P，再对已授权账号和内容完成真实验证。模拟、真实 I/O、界面和持续运行结果分别记录。以下均为必须验证的行为，不是目前已经完成的测试。

## 2 业务与目录

| 编号 | 场景 | 合格结果 |
| --- | --- | --- |
| B01 | 添加收藏夹、合集、单视频、番剧、电影 | 信息能浏览，来源和部分层级正确；没有用户下载动作时下载订单为零 |
| B02 | 打开页面刷新、定时或重复信息刷新 | 只更新信息；重复刷新合并，不能触发媒体下载 |
| B03 | 跨页筛选选择及排除，下载多 P 或若干集 | 最终文件与提交时清单一致，新加入来源的内容不混入 |
| B04 | 同一视频出现在两个来源 | 全部列表一条，各来源都可找到；同质量实体和正在执行的下载不重复 |
| B05 | 自己收藏夹移除、他人来源移除、刷新中断 | 各自符合产品规则；刷新失败不删除关系，已经归档内容保留 |
| B06 | 必要信息与补充信息缺失 | 必要缺失阻止完整归档，补充缺失明确警告；源站没有与下载失败可区分 |
| T01 | 空白新系统普通启动 | 不访问 Telegram、不自动扫描历史、不读取旧版游标 |
| T02 | 首次点击下载收藏增量 | 从 ID 1 扫描全部可访问历史；纯文本/照片/普通文件及照片加普通文件推进游标但不下载；含音视频单元的全部实际附件入队，含照片与逐附件侧车 |
| T03 | 再次同步、停机后新增、某附件失败 | 不漏新增、不重复已验证成果；失败附件仍可补齐，游标推进不丢任务 |
| T04 | 开关自动监控 | 未首次扫描不能启用；默认六十秒检查，已有同步时不积累重复任务 |
| T05 | 收藏夹唯一入口及跨页媒体组 | 链接下载返回 FEATURE_REMOVED；手动清单不得绕过收藏资格；按平台组完整收集，不拼相邻消息，跨页/跨增量不漏照片、不重复文件 |
| T06 | 收藏正文原位展开、附件与元数据 | 原省略正文被完整正文替换；每附件各一个 `<完整文件名>.metadata.json`，照片/侧车未完成时单元不能完整 |
| T07 | 时间与同秒冲突 | 消息时间按上海时区生成 `2001.01.01-10.11.12` 格式；消息 ID 为下一层，同批重试稳定，跨批同秒不覆盖；多条跨日期手工链接按各独立资源/媒体组确定时间，不整批归入最早日期 |
| Q01 | 多分享转存和自动追更 | 文件进入指定夸克目录；新增自动转存，但本机下载订单保持零 |
| Q02 | 网盘里选文件、选未展开文件夹、跨目录选择 | 后端正确展开选中范围；只下载清单内文件，后来的新增不自动下载 |
| Q03 | 用户提交下载 | 输出为 `Quark/<分享标识末八位>/<相对内容>`，无额外标题/日期层 |
| Q04 | 分享后缀撞名、含字母、链接有提取码参数 | 完整标识去重，目录键唯一稳定；不拿提取码、查询串或纯数字提取结果作身份 |
| Q05 | 转存失败、下载失败、分享失效、目标目录被删 | 阶段分别显示，其他条目继续；重试下载不重新转存，不猜替代目录 |
| Q06 | 追更新增、删除、同名变化 | 新增只转存，旧副本不因分享删除而被删除，不能无依据覆盖已下载版本 |
| Q07 | 纯文件夹选择及整批/逐条映射 | 根“我的云盘”，路径按真实父链拼接；同名不同 ID 独立；过期、删除、权限变化不回退其他目标；转存不生成下载订单 |
| Q08 | 夸克本批本机目标与不归档 | 复用公共冻结预览和订单，目录改变要求刷新；本机目标不改变云盘转存目标；新增文件不扩大订单，重启/重放不排入上传 |
| N02 | 关闭非成功提示、刷新及重复事件 | 点击仅隐藏提示，已读不解决；持久问题刷新恢复，同问题稳定 ID 更新，真正恢复后才解决 |
| D01 | 默认根与批次目录覆盖 | 默认使用同一个 downloadRoot；本批覆盖先通过执行端校验并固定 NONE 不归档策略，不修改全局根；云端目标单独配置 |
| D02 | 空间不足、中文路径、长文件名和非法路径 | 预检和运行中结果明确；不落到旧目录或云端挂载，不覆盖其他文件 |
| A01 | 本机完成后自动上传 | 下载与上传独立，未核对不能显示云端归档完成 |
| A02 | 上传中断、重复上传、云端缺项 | 本机保留，恢复只补上传/缺项，既有云端文件不生成无意义副本 |
| A03 | 清理本机副本 | 仅预览中符合条件的应用成果被清理，归档和旧版数据均不受影响 |
| N01 | 全新构建 | 不要求旧数据库、旧配置、旧 Python/PHP 服务或任何旧文件存在 |

## 3 故障与协议

| 编号 | 注入故障 | 验证重点 |
| --- | --- | --- |
| R01 | Java 接收任务后、调度前退出 | 重启后仍有同一任务且不重复创建 |
| R02 | Go 在下载中退出 | 只恢复该文件，已完成部分保持；不能有孤儿写入者抢同一路径 |
| R03 | 文件发布成功、上报前退出 | 根据收据和文件事实补报，不覆盖或重下已完成文件 |
| R04 | Java 提交结果成功、响应丢失 | Go 重发获得同一确认；只生成一份后续上传操作 |
| R05 | 远端转存/上传已接受但响应超时 | 进入核对路径，不无条件重复外部写入 |
| R06 | 心跳丢失、租约过期、旧结果延迟 | 不并发重做未确认操作，旧结果不能覆盖新状态 |
| R07 | 取消/暂停与完成同时发生 | 状态与已发生事实一致，不把已发布文件描述为从未产生 |
| R08 | 一个账号失效或某平台接口变化 | 隔离受影响任务，其他平台可浏览和运行 |
| R09 | Google Drive 不可用或核对不一致 | 本机成果不丢，状态不误报，上传恢复不触发平台下载 |
| R10 | 程序重启、网页关闭再打开 | 已记录暂停保持，后台任务不依赖浏览器存活 |
| R11 | 修改下载根时仍有任务 | 明确阻止或完成受控切换，不在同一任务中混用根目录版本 |
| R12 | 多实例同时启动 | 第二实例被拒绝，不能并发读写同一执行目录 |

## 4 构建与部署验收

发布产物能够在 Y7000P 配置好的运行环境启动，不依赖 Carbon 在线、网络共享目录、开发服务器或 Carbon 的绝对路径。正式数据库、会话、下载与缓存均位于 Y7000P 指定目录。先核实 Y7000P 的系统架构、运行账户、配置与工具版本，再执行部署验收；Carbon 构建成功不能代替这一项。

## 5 体验与运行基线

在 Y7000P、约一万条本地目录记录下，常用列表和搜索目标两秒以内返回；任务提交应立即给出受理反馈，外部平台解析耗时单独展示。含长正文、长文件名和部分失败的页面在规定桌面窗口与缩放下可读、可用。

持续七天运行期间安排至少一次 Java 重启、一次 Go 重启、一次电脑重启和两次短暂断网；任务不丢失、目录不错位、没有未经用户选择的 B 站/夸克下载，不出现错误归档完成。平台真实限制导致等待时允许保持待处理，但必须说明原因。

检查范围围绕本次功能。测试数据不得使用账号凭据或私人收藏正文进入仓库；远程真实动作、上传和账号使用遵守用户的准确授权。模拟通过只证明相应接口和故障分支，不宣称真实下载或长期运行已验收。

## 6 第一部分反馈的隔离验收

Java 本轮新增验证覆盖四种排序与上海日期边界、分页绑定查询、置顶重启持久化、分季身份、默认/空/精确轨道选择、人工/AI/未知字幕、内容与目录 revision 失效、跨选择的单文件占用、不同目标隔离，以及 NONE 策略在重试/重启/结果重放后不排上传。路径覆盖单视频、多 P 无副标题、按季番剧、电影语言、非法字符、大小写碰撞与标题刷新稳定性。HTTP 测试使用真实回环服务器和临时 SQLite。

以上是自动化用例范围；具体通过数量、Java-Go 本地跨进程结果与复现命令以模块 README 和本次 PR 为准。Bilibili 真账号、付费/地区内容、真实 Google Drive 挂载/归档、Y7000P 部署和七天运行仍需独立真实验收。第一部分没有实现第二部分 Telegram/夸克业务。
